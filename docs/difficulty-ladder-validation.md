# 十二档难度粗测

日期：2026-11-20。孩子实际反馈为能下旧 Thinker、0.4.4 原生最低档仍太难。用户选择统一约十二档、恢复旧 3–6 级并插入过渡档，先粗测后排序。正式参数见 [架构与规则](architecture.md#难度与提示)。

## 方法

- 使用随包 Stockfish 19 Lite WASM 的 Node CLI、`Hash=16`、`MultiPV=1`、关闭 `UCI_LimitStrength`，引擎分支按各档原本的 Skill、深度与时间搜索，取合法 `bestmove`。
- 经典档按实际概率在引擎与均匀随机合法走法间选择。保留旧 3 / 4 / 5 / 6 级的 35% / 60% / 85% / 100%、深度 3 / 5 / 8 / 12 和 900 ms 上限。额外过渡档为 45% / 深度 4、72% / 深度 6、93% / 深度 10。
- 每对八局：初始局面、`e4 e5`、`d4 d5`、`Nf3 Nf6` 各交换颜色一次。每局最多测试 160 个半回合；实际棋规和棋计为和棋，达到长度上限而未结束的棋局单列「未结束」，不当作和棋或按评分判胜。
- 第一轮 14 对、112 局，第二轮补六个交界、48 局，共 160 局。引擎进程复用，每次引擎搜索前 `ucinewgame`；未加应用的 500 ms 等待或 Worker 冷启动。随机数未固定种子。
- 本地实验脚本为被 Git 忽略的 `artifacts/compare-levels.mjs`，原始数据含棋谱，保存在 `artifacts/level-match-results.json` 和 `artifacts/level-match-crossings.json`。这些是本次粗排的证据，不是每次发布必须重跑的门禁。

## 排序结果

以下每行对应最终相邻的两个档位，胜负按「较低档胜 : 较高档胜」记录；和棋和未结束单列。

| 较低档 → 较高档 | 胜负 | 和棋 | 未结束 |
| --- | --- | --- | --- |
| 1 经典旧 3 → 2 过渡 45% | 0:5 | 1 | 2 |
| 2 过渡 45% → 3 经典旧 Thinker | 2:3 | 1 | 2 |
| 3 经典旧 Thinker → 4 过渡 72% | 0:5 | 0 | 3 |
| 4 过渡 72% → 5 原生 Skill 0 | 2:5 | 0 | 1 |
| 5 原生 Skill 0 → 6 经典旧 5 | 0:6 | 1 | 1 |
| 6 经典旧 5 → 7 原生 Skill 3 | 2:5 | 0 | 1 |
| 7 原生 Skill 3 → 8 原生 Skill 7 | 1:7 | 0 | 0 |
| 8 原生 Skill 7 → 9 过渡 93% | 1:5 | 0 | 2 |
| 9 过渡 93% → 10 原生 Skill 11 | 1:6 | 1 | 0 |
| 10 原生 Skill 11 → 11 原生 Skill 16 | 1:6 | 0 | 1 |
| 11 原生 Skill 16 → 12 Expert（旧 6） | 0:6 | 1 | 1 |

交叉结果说明不能机械拼接两套档位：原生 Skill 0 对旧 Thinker 是 6:0、1 和棋、1 未结束，但对旧第 5 级是 0:6、1 和棋、1 未结束；93% 过渡档则胜过原生 Skill 7，又输给 Skill 11。因此使用统一穿插顺序。

## 边界

每对只有八局，结果是排序依据之一，不是统计上精确的棋力标定；未结束棋局可能改变最终比分。没有测 Elo，也不能承诺相邻档等距、每一局都严格递增，或随机分支符合人类新手的错误方式。下轮应以孩子在新第 3 档附近的实际试玩为准，而不是继续堆叠档位或给分数标签。
